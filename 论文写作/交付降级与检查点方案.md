# 交付降级与检查点方案

## 检查点

1. `Q1`：存在 `outputs/question1_analysis/q1_city_daily_annual_constrained.csv`；
2. `Q2`：存在年度、三区日级、日级模型比较和区域 conformal 校准表；
3. `Q3`：存在绝对资源日计划、资源敏感性和 P+R 缺口表；
4. `Q4`：存在活动、阴雨和鲁棒性结果表。

只有四个检查点均通过，才交付“全模型版”。

## 全项目降级路径

若重跑 Q1--Q4 任一模型失败、或新数据改变了输入口径，则停止使用新生成的数值，切换为“已验证产物版”：仅交付最近一次通过全量测试后生成的四问 CSV、图和质量报告，并在摘要/结论标注“基于已冻结输入与已验证运行的情景结果”。不得混合失败运行产生的任一新表。

若 Q2 日级模型不可用，则只保留全市年度预测和问题一相对压力图；Q3、Q4改为定性资源触发建议，不再报告绝对泊位、车辆和人员数。若 Q3 不可用，则 Q4只报告事件/降雨对需求的方向性冲击，不再声称重优化配置。该路径覆盖四问，避免前后口径混用。

## 启用记录

每次交付在 README 或论文附录记录：运行日期、输入版本、通过的测试数、采用“全模型版”或“已验证产物版”、以及触发降级的具体检查点。
